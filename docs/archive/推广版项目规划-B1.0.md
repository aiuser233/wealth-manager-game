## 1. 战略判断：银行推广的三道门

1. **合规门**：培训部门/合规部门审内容。过不了这关，一切白搭。
   - 每条教学内容可追溯到公开监管依据（"source_note"）
   - 双审制流程落地为数据结构（初审/终审标记）
   - 无真实标的、数据不出本机、免责声明完备
2. **价值门**：培训部门要看到学习效果，预算才批得下来。
   - 个人：学习报告可导出
   - 团队：按网点聚合的通过率/弱项地图
   - 行内：定制题包接口（每家银行都有自己的产品与话术）
3. **习惯门**：理财经理要用起来，必须碎片时间可玩。
   - 移动 H5 形态优先于桌面
   - 单局节奏 ≤5 分钟（每日一题、一周一考、剧情一幕）
   - 无强制在线、进度自动保存

**结论**：三道门对应三条并行工作线——内容生产线、B 端功能、形态适配。内容生产线是产能基础，永远优先。

## 3. P1 内容产能基建（当前执行）

### 3.1 content-tools 管线

**目标**：内容从"改 TS 代码"变成"写 JSON 数据包"，让文案/审校/行内人员并行生产。

```
tools/content-tools/
├── schema/            # 各内容类型的 JSON Schema
│   ├── question.schema.json      # 题目
│   ├── knowledge.schema.json     # 知识词条
│   ├── quest.schema.json         # 剧情任务
│   ├── lifeline.schema.json      # 人生线
│   ├── event.schema.json         # 事件
│   └── common.schema.json        # 公共：审核标记、来源引用
├── rules/             # 内容 Lint 规则
│   ├── banned-words.js           # 禁语词表（"保本""稳赚""内部消息"等）
│   ├── term-consistency.js       # 术语一致性（架空机构名表）
│   ├── era-check.js              # 年代合理性（2013 年不得出现"直播间投诉"）
│   └── risk-words.js             # 合规风险词预警
└── build.mjs          # 校验+编译：JSON → TS 数据包，失败即 CI 红灯
```

**验收**：把一个 JSON 文件写错（缺字段/含禁语/年代穿越），`npm run content:build` 必须报错并指出文件与行。

### 3.2 双审制数据结构（合规门的基石）

所有教学内容（题目/词条/剧情/复盘卡）统一附加：

```jsonc
{
  "review": {
    "status": "draft" | "reviewed" | "approved",
    "source_notes": ["资管新规（2018）第X条", "存款保险条例（2015）"],  // 公开依据引用
    "k_reviewer": null,   // 金融知识审校人
    "c_reviewer": null,   // 合规表述审校人
    "reviewed_at": null,
    "era_note": "2018 年前后规则差异：……"   // 分年代教学点
  }
}
```

- 内容加载时 `status !== 'approved'` 的条目仅进入开发模式，不进正式包（先留开关，P4 培训包强制启用）
- 历史存量内容（485 题/20 词条）批量补 `source_notes`，状态置 `draft` 待审

### 3.3 知识库扩量（20 → 60+，本阶段）

按 8.1 大纲补齐五个职级段的缺口，重点：
- 基础篇（+10）：征信、账户分类、反洗钱义务、支付工具、银行理财发展简史
- 产品篇（+10）：债券久期、封闭式/定开、雪球补充、银行保险、金币金条与账户金
- 市场篇（+10）：M1/M2 与利率、社融、北向资金、涨跌停与流动性、基金抱团机理
- 规划篇（+10）：债务优化、收入结构、育儿财务、赡养规划、大病应对
- 行为篇（+10）：损失厌恶、心理账户、控制幻觉、幸存者偏差、框架效应伦理

每条带 `source_notes`（引用公开规则/经典文献），置 `draft` 待审。

### 3.4 两条示范人生线（"剧情即案例课"的完整体感）

**王秀兰线（9 节点）**：2006 存折利息税 → 2007 疯牛劝阻（第一次顶点）→ 2007 5·30 → 2008 养老钱腰斩安抚 → 2009 退休三桶金方案 → 2011 负利率追问 → 2013 被宝宝类吸引 → 2015 高息集资骗局拦截 → 2020 退休方案落地
**李建国线（9 节点）**：2006 新婚定投启蒙 → 2009 购房 vs 投资 → 2011 二胎财务压力 → 2013 利率市场化转贷 → 2015 场外配资的诱惑（邻居赚了）→ 2015 股灾断供边缘 → 2018 P2P 血汗钱 → 2022 子女留学金保卫 → 2025 养老启动

验收：E2E 按日期+信任触发，节点文案双角色以上，每节点带教学 tag 与知识解锁。

## 4. P2 卷一成品化要点（规划）

- **行情 K 线图**：行情终端加宽基/行业日 K（近 60 日），SVG 自绘，无新依赖
- **存档补全**：接待会话中间态、考试进行态、剧情 pending 全部入档；容量警戒（localStorage 4MB 预算）
- **学习报告**：个人 PDF 导出（考证记录/错题图谱/生涯大事记/合规记录）
- **移动自适应**：断点 <768px 单列布局，触控目标 ≥44px，聊天式剧情
- **新手引导**：前 3 个交易日强制引导（AP、接待、行情、剧情四教学点）
- **结局闭环 v0**：卷一结束按"业绩/专业/红线"三维给阶段性评语（完整六结局留 P6）

## 5. P3 形态（规划）

- **Tauri 2 Windows 壳**：窗口/文件存档（替换 localStorage）/自动更新占位；Mac 构建验证顺带
- **移动 H5**：与桌面同代码，断点适配；微信内打开的兼容（无 localStorage 依赖的会话内存档兜底）
- 私有化预留：静态资源 + JSON 内容包整体可打包为离线包

## 6. P4 培训后台（规划）

- **聚合报表**：网点/团队/个人三级——通过率、弱项地图、活跃度、剧情抉择分布（best/good/normal/bad 是天然的态度数据）
- **行内题包**：`content/custom/*.json` 热加载，附 Schema 校验与禁语 Lint（银行合规部门可直接提交题包）
- **讲师模式**：大屏放"关键行情日"，全班同步做抉择，实时看分支分布
- **账号与私有化**：离线优先，匿名本地学习记录 + 可选的集中收集端点（银行内网）

## 7. P5/P6 内容与游戏性（规划）

- 知识库 300+、题库 3600+：P1 管线建成后按人周产出节奏推进
- 卷二~五剧情每卷 10-12 任务 + 对应年代人生线（2013 钱荒、2015 配资、2018 贸易战、2020 疫情、2022 破净潮、2024 9·24）
- 12 条人生线全量（含世代交替：子女继承关系）
- 团队管理（带 3-5 下属）、六结局、二周目扰动（关键事件 ±1 季度漂移）
- 美术：轻度二次元立绘 AI 初稿 + 人工精修；BGM/音效 25+60

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 银行合规部门对"游戏"二字敏感 | 定位话术："情景化合规培训系统"，游戏性是载体不是卖点；先拿 P1 的审校数据结构给合规部门看 |
| 内容错误引发客户纠纷 | 双审制 + source_notes 可追溯 + 全程免责声明；题库标注"参考公开大纲改编" |
| 行内数据安全 | 纯单机/内网部署，无外联；学习记录匿名化可选项 |
| 单人产能 | 管线化让 AI 供初稿、审校守质量；内容与代码彻底分离 |
| 体量膨胀失控 | 每阶段验收标准先行，未达标不进下一阶段 |

## 9. 度量指标（每阶段 review）

- 内容：词条数、题库数、双审通过率、禁语 Lint 通过率
- 培训：模拟试点班级的通过率提升、弱项地图变化
- 游戏：蒙特卡洛结局分布、晋升时点分布、数值无发散
- 工程：typecheck/test/build/sim/bot 五管线全绿为基线

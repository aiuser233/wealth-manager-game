# 《重生之我是理财经理》朋友公测前修改建议书

| 项目 | 内容 |
|---|---|
| 文档性质 | 执行记录稿；已按用户批准范围落地，人工内容审校仍单独保留 |
| 评审日期 | 2026-09-17 |
| 建议目标版本 | Web 朋友封闭公测版 v0.2 |
| 目标人群 | 首批 5–15 位朋友，以桌面浏览器体验为主 |

## 一、结论先行

项目已经不是“缺内容的原型”：核心循环、20 年市场、剧情、客户、考试、存档、团队、结局和内容工具链都已形成，自动测试与数值模拟基础也明显强于普通个人项目。

但它目前更接近一个**功能和内容非常丰富的开发版**，还不是可以放心交给陌生玩家的公测版。公测前最值得投入的工作不是继续增加题目、客户或系统，而是完成下面五个收口：

1. **把玩家入口收窄**：从“十二个并列后台页”改成清晰的游戏主路径。
2. **把内容数量变成内容质量**：去掉大量重复题，完成公测范围的人工审校。
3. **让不同玩法真正导向不同结果**：重新校准晋升、路线与结局分化。
4. **保证网页版本不丢档、不黑屏、出错可反馈**：补齐发布工程与恢复机制。
5. **用真实玩家验证前 30 分钟和长期节奏**：自动化只能证明不崩，不能证明好玩。

我的总体判断是：**完成 P0 项后适合进行朋友封闭公测；不建议以“正式考试/专业培训产品”名义直接公开传播。**

### 执行进度（2026-09-17）

用户确认“除人工校验外开始执行”后，首批已落地：

- ✅ 玩家入口收口：五个主入口 +“更多”，培训后台/讲师模式默认隐藏。
- ✅ 开始页重做：继续游戏、新生涯、高级 seed、开局行情加载反馈、旧档导出。
- ✅ 工作台“当前目标”提示。
- ✅ 公测题池完整去重：5089 条源记录 → 3841 道唯一题，去除 1248 条完整重复；知识标签合并保留。
- ✅ 结局分流：专业、销售管理、均衡管理三类路线不再被同一结局吞并；机器人报表增加路线指标。
- ✅ 存档 schema v3：版本校验、未来版本拒绝、5 MB 导入限制、读档前自动恢复备份。
- ✅ 正式考审校状态显式化：过审题不足时不展示正式入口，两门唯一题较少的专项按 10 题 Beta 卷运行。
- ✅ 错误兜底、诊断信息复制、隐私与公测免责声明。
- ✅ GitHub CI、Netlify 静态部署配置、版本清单。
- ✅ Playwright 真实浏览器回归：桌面+手机均跑通新游戏、教程、行情、存档、刷新、继续游戏。
- ⏳ 人工双审按用户要求留待后续，不在本批自动执行。

尚需真实朋友参与的观察轮、耐玩轮及人工内容审校，不应由机器结果替代。

## 二、评审依据与当前信号

### 2.1 已具备的优势

- 核心系统完整：日/周/月时间帧、行动、接待、行情、客户、考试、剧情、团队、结局均已实现。
- 内容覆盖广：5089 题、276 词条、90 章主线、13 条人生线、140 个导演事件。
- 工程分层健康：core、content、ui、tools 职责明确，可无头模拟。
- 发布体积可控：当前生产包主 JS 约 2.4 MB，gzip 后约 638 KB，静态托管可行。
- 自动质量门槛较好：类型检查、单元测试、内容检查、20 年模拟和机器人长测均可运行。
- 浏览器存档已经具备自动档、手动档和 JSON 导入导出能力。

### 2.2 公测前暴露出的关键问题

| 信号 | 当前观察 | 影响 |
|---|---:|---|
| 题库完整重复 | 5089 题中，按“题干+选项+答案+解析”统计仅 3841 个唯一组合；1248 题为重复冗余 | 玩家频繁遇到同题，削弱专业感；题量指标失真 |
| 人工双审 | 绝大多数内容仍为 draft；正式考试门禁因此不可用 | 不能对外宣传为经过审校的专业考试内容 |
| 结局分布 | 最近一次 pro/sales/balanced 各 20 局，共 60 局全部进入“独立财富顾问·开办家办” | 路线选择与结局缺少可感知差异，重玩价值不足 |
| 首屏版本信息 | 开始页仍写“M0 核心原型 · 2006–2025”，系统页仍写“M1 开发版”，实际内容已到 2027 | 第一印象像未收口的内部版本 |
| 导航复杂度 | 顶栏同时呈现工作台、市场、客户、考试、图鉴、系统、团队、成就、档案、培训后台、讲师模式、手册 | 新玩家无法判断“现在最应该做什么”；B 端功能干扰游戏路径 |
| 开局性能 | 开局同步预演 2000–2006 共 1566 个行情快照 | 较慢设备可能出现按钮点击后短暂无响应，需要加载态或后台化 |
| 自动化覆盖 | 有大量单元测试，但缺少真实浏览器端到端发布烟测和全局错误兜底 | 部署后仍可能出现黑屏、弹窗焦点、移动端布局或存档流程问题 |
| 可访问性 | 大部分弹窗缺少 dialog 语义、焦点管理、Esc/键盘路径 | 键盘用户体验差，也容易出现弹窗后焦点丢失 |
| 公测反馈 | 尚无游戏内反馈入口、版本号、诊断信息一键复制和更新说明 | 玩家说“有问题”时很难还原现场 |

## 三、建议的公测产品定位

首轮建议明确定位为：

> **朋友封闭体验版：验证重生题材、银行职场循环、剧情选择和学习玩法是否有吸引力。**

首轮不应承诺：

- 不宣称题库已经达到真实考试替代或权威培训标准。
- 不开放账号、排行榜、云存档等在线服务承诺。
- 不以移动端为第一验收平台，除非决定专门投入移动交互重构。
- 不把培训后台和讲师模式放在普通玩家的默认导航中。

建议首轮支持环境：最新版 Chrome、Edge 桌面浏览器，1366×768 以上；手机仅标记“实验支持”。这样能显著减少首轮测试变量。

## 四、P0：朋友公测前必须完成

### P0-1 玩家信息架构与首屏重做

**问题**：功能丰富但入口平铺，普通玩家看到的是工具集合，不是游戏旅程。

**建议**：

- 默认主导航只保留 5 个核心入口：`工作台 / 客户 / 行情 / 学习 / 生涯`。
- `团队`根据年份和职级解锁后出现，不在 2006 开局占位。
- `成就、档案、设置、手册`收入“更多”菜单或生涯页。
- `培训后台、讲师模式`改为独立模式入口、特殊 URL 或开发开关，普通玩家默认不可见。
- 工作台增加“当前目标”卡：主线目标、KPI 缺口、推荐行动、下一个关键日期。
- 开始页优先提供“继续游戏”和“开始新生涯”；随机 seed 收入高级选项。
- 清理 M0/M1、2006–2025 等过期文案，统一为明确版本号和公测标识。

**验收标准**：第一次玩的用户在无人讲解时，3 分钟内能说清楚当前目标并完成第一次有效行动。

### P0-2 首次 30 分钟体验与节奏收口

**问题**：五步文字引导介绍了功能，却没有形成“目标—行动—结果—成长”的连续教学关；20 年流程也容易变成重复点击行动与结算。

**建议**：

- 把 2006 年第一个月做成明确的垂直切片：入职晨会 → 第一次接待 → 第一次产品匹配 → 第一次行情波动 → 月末 KPI 结算。
- 教学提示绑定真实控件并分步触发，不一次性用遮罩读完说明。
- 每次行动后突出“为什么发生这些数值变化”，弱化日志堆叠。
- 增加“推荐行动”，但允许玩家忽略，避免变成强制教程。
- 尽早给一次小成功、一次有后果的选择和一次客户回访，让游戏卖点在首局出现。
- 开局行情预热增加加载反馈；必要时分帧执行，避免页面假死。
- 在周/月帧成熟后提供“推进到下一剧情/数据日”的安全快进。

**验收标准**：至少 80% 的首测玩家能完成第一个月；首 30 分钟内能体验接待、行情、剧情选择和月结四个卖点。

### P0-3 题库去重与有限范围人工审校

**问题**：题库数量很大，但 1248 道完整重复题会直接伤害公测观感；全部内容仍做人工双审并不现实，也不应在公测前继续追求题量。

**建议**：

1. 先按“题干+选项+答案+解析”生成稳定指纹，删除或合并 1248 道完全重复题。
2. 再检查近似重复：只换人名、顺序或场景包装但知识点和答案完全相同的题。
3. 建立重复率机器闸：完整重复必须为 0；同知识点的近似题设定合理上限。
4. 首轮只人工审校公测实际可抽到的核心池，例如每科 100–200 道高质量题，而不是急着审 5000 道。
5. 已审内容标记 approved；未审内容只进入“练习题 Beta”，不进入正式考试。
6. 公测版可以暂时隐藏“正式考”，或明确写出“正式题库审校中”。

**验收标准**：完整重复为 0；核心公测题池 100% 人工复核答案、解析、年代口径和来源；玩家连续练习 50 题不出现完全相同题。

### P0-4 数值路线与结局重新校准

**问题**：三种机器人策略 60 局进入同一结局，说明当前结局系统虽有七个结果，但自动策略未形成路线分化。

**建议**：

- 先区分“机器人模型不真实”还是“判定条件失衡”，不要仅调整结局阈值。
- 为三条主要路线定义清晰的中间指标：业绩路线、专业路线、管理路线各自应牺牲什么、获得什么。
- 将结局条件改为多维相对优势，而不是若干高值条件同时满足后被同一高优先级结局吞掉。
- 增加结局判定解释页：明确告诉玩家哪些长期行为塑造了结果。
- 机器人报告新增：各结局占比、各路线属性轨迹、关键抉择分布、未触发结局的最近距离。
- 用真实玩家存档回放补充机器人验证；机器人不能模拟剧情理解和玩家犹豫。

**建议目标**：三种策略的主结局应明显不同；任何一个正常结局不应在全部策略合计中长期超过约 50%，除非这是明确设计意图。

### P0-5 存档安全与版本迁移

**问题**：网页公测会持续更新；浏览器 localStorage 可靠但不是永久云盘。更新、清缓存、隐私模式、存档损坏和旧格式迁移都会成为真实问题。

**建议**：

- 存档结构增加明确的 schemaVersion、gameVersion、createdAt、updatedAt。
- 导入存档前执行结构与大小校验，错误字段给出可理解提示，不直接进入重放流程。
- 读档或覆盖手动档前二次确认，并先创建一个可恢复备份。
- 每次版本迁移保留迁移器，不只兼容 cursor；为旧版本准备 fixture 回归测试。
- 明确提示：“存档保存在当前浏览器，清除网站数据会丢失”。
- 在完成一个章节、年度或重大事件后提示玩家导出备份。
- 公测网址确定后不要随意更换域名或路径，因为不同 origin 的 localStorage 不互通。
- 上线前实际测试：刷新、关闭重开、版本更新、损坏档、旧档、导入超大文件。

**验收标准**：新档、当前档和至少两个旧版本 fixture 均能读入；损坏档不会黑屏；覆盖操作可恢复。

### P0-6 发布可靠性与浏览器端到端测试

**问题**：当前测试更擅长证明引擎逻辑正确，尚不能证明“部署后的网页可以被朋友顺利玩”。

**建议**：

- 建立 CI：`content:check → typecheck → test → build`，失败不得部署。
- 增加最小浏览器 E2E 流程：打开页面、新游戏、完成教程、行动、结算、进入行情、存档、刷新、读档、做一道题。
- 为桌面 1366×768、1920×1080 和一个手机视口做截图回归或人工清单。
- 增加全局错误边界与友好错误页，提供“导出诊断信息/返回首页”，避免白屏。
- 固定版本号、构建时间和变更日志；玩家反馈必须能带上版本号。
- 部署启用 HTTPS、压缩、长缓存静态资源与 `index.html` 短缓存。
- 正式发布前用生产构建而非 Vite 开发服务器进行整轮试玩。

**验收标准**：部署后核心 E2E 全绿；新玩家遇到运行错误时能恢复并提供可定位信息。

### P0-7 公测反馈闭环、隐私与免责声明

**建议**：

- 增加“反馈问题”入口，至少生成可复制的诊断模板：版本、日期、seed、当前页面、浏览器、最近 20 条日志；存档只能由玩家主动选择是否附带。
- 首轮可以用问卷或群聊收集反馈，不必立刻建设服务器。
- 如果启用学习记录收集端点，必须默认关闭，并在发送前说明发送哪些字段、用途和保存期限。
- 提供简短隐私说明：默认存档仅在本机、是否使用 Cookie、是否收集数据、如何删除。
- 保留“不构成投资建议”，并补充“题库处于公测审校阶段”。
- 对 AFP、CFP 等名称和考试相关描述做一次商标/品牌使用检查，避免造成官方合作或官方题库的误解。

## 五、P1：可以在公测期间持续完善

### P1-1 全局视觉和交互系统统一

- 统一卡片、标题、间距、按钮层级、空状态、加载态和反馈 Toast。
- 减少每个页面自行定义一套按钮和面板样式。
- 对弹窗补齐 `role=dialog`、标题关联、焦点锁定、关闭后焦点恢复和键盘操作。
- 为颜色涨跌之外增加图标或文字，避免只靠红绿表达。
- 检查 1366×768 下所有页面，避免内容只能靠浏览器缩放才能看全。

### P1-2 长期循环的差异化

- 行动不应只是相同按钮换随机文案，应由客户、年代、市场状态和职业路线改变收益与风险。
- 晨会、周计划、月结和年度总结形成不同时间尺度的仪式感。
- 将客户回访、转介绍、投诉、持仓亏损和人生线更明显地回接到工作台决策。
- 为“重复劳动”提供批量/委派机制，把玩家注意力留给关键抉择。

### P1-3 剧情表现力

- 现阶段不必追求大量立绘，可先补低成本高收益内容：背景色调、章节封面、角色表情差分、关键事件插图、少量 UI 音效。
- 对前 30 分钟和每卷开头/结尾优先制作，不平均铺满全游戏。
- 增加文本速度、自动播放、历史回看和跳过已读等视觉小说基础功能。

### P1-4 性能与包体

- 将培训后台、讲师模式、题库批次和非首屏内容按路由懒加载。
- 开局市场预热放入 Web Worker 或分帧任务，并展示进度。
- 对低端设备测量首次加载、首次可交互和新游戏启动耗时，再决定是否优化。

### P1-5 公测数据观察

在玩家明确同意的前提下，只收集最少量匿名事件：

- 是否成功开始/继续游戏。
- 首次行动、首次接待、首次月结是否完成。
- 每次会话时长与退出位置。
- 最常用/最少用页面。
- 卡关任务、读档失败和前端错误。

首轮样本很小，访谈和观察应优先于复杂埋点。

## 六、P2：朋友公测后再决定

- 云账号与跨设备存档。
- 排行榜、分享卡、成就分享。
- PWA 离线安装与自动更新。
- 手机专用交互版本。
- 完整 BGM、角色立绘、背景与事件插画。
- 创意工坊和玩家自制事件包。
- 银行内网、讲师后台和正式培训产品路线。

这些工作成本高，也会引入账号安全、隐私、内容审核和运营责任，不应阻塞第一轮朋友测试。

## 七、建议执行批次

### 批次 A：公测止血版

范围：版本文案、模式隔离、玩家导航、开局加载态、存档提示与反馈入口。

目标：朋友能打开、理解、开始、保存、反馈。

### 批次 B：质量收口版

范围：完整题目去重、核心题池人工复核、正式考试公测策略、结局与路线校准。

目标：重复感显著降低，专业内容不误导，玩法选择有长期差异。

### 批次 C：发布工程版

范围：部署配置、CI、E2E、错误兜底、版本迁移 fixture、生产环境烟测。

目标：每次更新可重复发布，不靠开发者现场救火。

### 批次 D：封闭公测

建议分两轮：

1. **观察轮（3–5 人）**：尽量不指导，现场观察首次 30–60 分钟。
2. **耐玩轮（5–15 人）**：允许自由玩一周，收集存档、问卷与访谈。

每轮结束先修共性问题，再扩大人数，不要一开始把链接广泛传播。

## 八、公测验收指标

| 维度 | 建议指标 |
|---|---|
| 可进入 | 受测环境中页面打开与新游戏成功率 100% |
| 首次理解 | 80% 玩家在 3 分钟内完成第一次有效行动 |
| 首月完成 | 80% 玩家完成 2006 年第一个月 |
| 存档 | 刷新、关闭重开和版本更新后恢复成功率 100% |
| 稳定性 | 不出现阻断继续游戏的白屏/死档；阻断问题必须能导出诊断 |
| 内容重复 | 公测核心题池完整重复为 0 |
| 内容可信 | 核心公测题池人工审校率 100% |
| 路线分化 | 不同策略/真实玩家产生可解释的属性、晋升和结局差异 |
| 操作清晰 | “我不知道接下来做什么”不进入前三大反馈 |
| 主观体验 | 愿意再次打开游戏的玩家达到首批样本的 60% 以上 |

首轮人数少，百分比只用于发现方向，不应包装成统计学结论。

## 九、需要先商定的八个决策

在实施前，建议先逐项定案：

1. 公测定位是“朋友娱乐体验”还是“专业培训预试用”？建议前者。
2. 首轮是否只保证桌面 Chrome/Edge？建议是。
3. 是否把培训后台和讲师模式从玩家导航隐藏？建议隐藏。
4. 正式考试在人工审校前是隐藏，还是保留锁定说明？建议隐藏或改名“考试预览”。
5. 是否接受删除 1248 道完整重复题，并停止追求 5000+ 数字？建议接受。
6. 是否同意重做结局判定，使三种路线真正分化？建议同意。
7. 是否收集匿名使用数据？建议首轮不自动收集，以问卷和玩家主动导出诊断为主。
8. 公测网页是否长期使用同一域名？建议上线前确定，避免 localStorage 存档随域名变化而丢失。

## 十、建议冻结项

在上述 P0 完成前，建议暂时冻结：

- 新增大批题目、词条、产品、客户和导演事件。
- 新增大型玩法系统。
- 云账号、排行榜和多人功能。
- 全量美术资产生产。

原因不是这些方向没有价值，而是当前最大收益来自**收口、删减、校准和真实试玩**。项目现在需要从“证明能做很多”切换到“让玩家顺畅地感受到最好的部分”。
